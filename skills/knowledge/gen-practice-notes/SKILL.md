# 实践笔记生成（gen-practice-notes）

目标：把一次性的过程知识，变成下次可复用的短文。判断标准只有一条——**下次遇到同类任务，读它能不能少走弯路**。读不出这条价值的候选，不写。

## 执行流程

### 1. 收集候选
扫当前对话：用户纠正过的做法、踩过的坑、反复确认的约定、工具参数与环境差异、被否决的方案及原因。

排除：一次性命令输出、可从代码或官方文档查到的事实、纯时间线进度、没有结论的讨论。

一条候选对应一个“结论 + 依据”。“记得先跑 lint” 不是笔记；“提交前跑 lint，因为 CI 只在 PR 上跑，本地不跑会浪费一轮 review” 才是。

粒度：同一事故、同一主题优先合并成一条。只有两部分内容会在不同场景被独立检索时才拆（比如“我怕踩坑”查 `pitfalls/`，“我要写重试”查 `best-practices/`），拆完互相链接。拆得越碎，下次越找不到——笔记库的价值在密度，不在条数。

### 2. 查重
先读 `docs/practice-notes/README.md` 和目标分类目录，看有没有同名或主题重叠的条目。重叠时不要自作主张，把三种处理方式摆给用户：合并进已有条目 / 新建独立条目 / 跳过。

### 3. 反馈提纲（此步不写文件）
按下面格式输出，每条一块：

---
**标题**：提交前本地跑 lint
**分类**：workflow
**tags**：[git, ci, lint]
**拟存路径**：docs/practice-notes/workflow/pre-commit-lint.md
**摘要**：
- CI 只在 PR 触发，本地不跑 lint 会多一轮 review 往返
- 命令与失败时的常见报错
- 与已有条目 `xxx.md` 的关系：无 / 合并 / 需拆分
---

末尾附一句：共 N 条，确认后写入。然后停下等用户回话。

### 4. 写入（用户允许后）
- 目录不存在则创建；默认根 `docs/practice-notes/`，用户已指定或已有分类体系时以用户为准
- 一条笔记一个 `.md`，文件名 kebab-case 英文短名
- 同名文件已存在：不覆盖，先合并或再问一次
- 写完补索引，不留孤儿条目

### 5. 更新索引
`README.md` 表格逐条追加，保持列为：标题 | 分类 | tags | 路径 | 更新时间。索引顺序按分类分组，组内按更新时间倒序。

### 6. 回报
列出写入路径 + 每条一行变更摘要 + 索引是否已更新。

## 文件模板

```markdown
---
title: 提交前本地跑 lint
category: workflow
tags: [git, ci, lint]
created: 2026-10-30
updated: 2026-10-30
source: 2026-10-30 会话，修复 CI 失败
---

## 场景
什么时候会遇到。

## 做法
可执行步骤或判断规则。

## 原因
为什么这样做，不这么做会怎样。

## 反例
踩过的坑，附现象或报错。
```

`source` 记录来源（会话、issue、PR 链接），让后来人能追到上下文。日期用 ISO `YYYY-MM-DD`。tags 用 YAML 列表，不用逗号串。

## 默认分类
- `workflow/` 流程、顺序、协作约定
- `best-practices/` 推荐做法、可复用模式
- `pitfalls/` 易错点、反例
- `tools/` 命令、参数、环境配置

跨类内容归主类，其余靠 tags 关联。用户体系优先于本表。

## 边界
- 零候选：直接说“这次没有值得沉淀的点”，不要凑数
- 用户否决或改分类：按用户说的改，不写入未被允许的文件
- 笔记内容必须来自真实对话或工作产物；缺依据的推断要么标注“待验证”，要么不写
- 索引与文件必须一致：新增条目必须进索引，删除条目必须删索引
